OPPO Enco earbuds on your Mac

The Enco line is where this protocol comes from: the vendor's serial service is named after OPPO, and the OnePlus and realme earbuds that answer it are the same protocol under other names. What no Enco model has yet is a recording in this project — and a recording is the only thing that turns a connection from readable into writable.

Why a Mac sees an audio device and nothing else

Every setting on an Enco earbud — the noise mode, the equalizer, BassWave, which gesture does what — lives on a separate vendor control channel, carried over a Bluetooth serial service. Pairing happens in System Settings, and macOS will connect and disconnect the earbuds happily, but no Apple software opens that other channel. So the noise mode you set last week from the phone is still in force, with no way to see it or change it from the Mac.

BudsDesk opens that channel. It is the whole reason the app exists: not a nicer Bluetooth pane, but the missing half of the earbud's own interface.

That UUID is the gate rather than an identifier: every member of the family publishes it, which is what makes an Enco earbud a candidate for this app at all. The channel number beside it is read out of the device's own SDP record every time rather than hard-coded, because a model is free to put the service somewhere else.

What an Enco connection shows today

Connect an OPPO Enco model that advertises the control service and BudsDesk will have a session with it. What you see is what the earbuds say, and nothing is written:

Read

Battery where the earbuds report it per bud, wear state, the active noise-control mode, the equalizer preset, the codec the link negotiated, and the firmware string verbatim.

Not written

No mode, preset, BassWave level or gesture is changed, because no Enco model has been recorded here yet. Every such control is drawn disabled with the reason on the card.

Never

Firmware. Updates travel over a different service that this app does not open at all — a failed firmware write bricks hardware, and nothing here is worth that risk.

If your Enco earbuds report nothing at all, that is a result too. A model that answers the service but has no state to give is telling you it speaks a different generation of this protocol — and the app says so, instead of showing you defaults dressed up as readings.

How an Enco model becomes writable

Somebody records it. Tracing on, one setting changed at a time, the traffic written out as hex, and the recording committed with its provenance: model, firmware string, date, tool and channel. Then one JSON file in devices/ describing what the recording shows, each capability marked measured, inferred or unconfirmed with its evidence cited. It is a file, not a build.

The supported-models page has the full recipe and the rules the registry enforces — including the one that matters most here: a capability only gets a write path if it is measured.

Questions

Does BudsDesk work with my OPPO Enco model?
If it advertises the vendor's control service, yes — it will connect and show what it reports: battery per bud where the earbuds supply it, wear state, the active noise mode, the equalizer preset, the codec and the firmware string. It will not write any setting until that exact model has been recorded here, because writing a value nobody has seen that model accept risks leaving it in a state the app cannot describe or undo. If your model does not publish the service, nothing is sent at all.
Why does the app call my OPPO Enco earbuds read-only?
Because no Enco model has been recorded in this project yet. Read-only is a statement about evidence rather than about the hardware: the protocol is shared, so a read-only connection is the expected result, and every control that would write is drawn disabled with the reason printed on it. The window's footer reads "Verified write paths: none" — which is a fact about this repository, not a verdict on your earbuds.
Does BudsDesk import my settings from the OPPO phone app?
No, and it does not need to. Every setting lives on the earbuds themselves, so the app asks the hardware what its state is and shows the answer. There is no account, no cloud copy and no transfer from the phone — the earbuds are the single source of truth for both apps.
Is there an official OPPO app for the Mac?
No vendor ships a desktop app for these earbuds, and none of this project's code comes from one. BudsDesk is independent and open source, written by recording what the earbuds' control channel carries; it is not affiliated with OPPO or BBK Electronics.

The other two brands

The same channel serves OnePlus Buds and realme Buds. OnePlus has the single measured model so far; for the rest of the family the rule is the same — connect and read today, writable once somebody records it.
