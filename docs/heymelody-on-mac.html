HeyMelody on a Mac, honestly

People search for this because the phone app is the only thing that ever worked. So here is what is actually true, including the parts that are not flattering to BudsDesk.

What we can state, and what we will not

HeyMelody is published for iPhone and Android. There is no desktop build. Some App Store storefronts offer it for Apple silicon Macs, which is Apple's standard mechanism for running an unmodified iPhone app on a Mac.

What we have not tested: whether it can reach the earbuds' control channel when running that way. Bluetooth access for an iPhone app on a Mac goes through a compatibility layer, and the honest answer is that we do not know what it does here. Any page that states flatly that the phone app "does not work on a Mac" is asserting something it has not checked, and we are not going to.

What follows is about architecture, not about which app wins a test nobody has run.

Where the phone app does more than BudsDesk

  • Firmware updates. It does them. BudsDesk will not, ever — the update channel is never opened by this app. If your earbuds need a fix from the vendor, that app is the only tool here that can apply it.
  • Model coverage. It knows dozens of models. BudsDesk has one measured end to end.
  • Editing a custom equalizer curve. The phone app builds one; BudsDesk only offers the custom slot once a curve already exists on the earbuds.

None of that is a small list. If those are what you need, use the phone app — and the rest of this page is about the times when the phone is not the machine you are sitting at.

"Network access: none" is worth spelling out. BudsDesk has no telemetry, no analytics, no account and no update check. It can be run with the network down and behaves identically. That is a consequence of it being a small, single-purpose tool, and it is checkable in the source rather than promised in a policy.

Shared settings, not competing ones

The settings live on the earbuds. Change the noise mode from the Mac and the phone app will show the same mode; change a preset on the phone and BudsDesk will read it back the next time it polls. There is no sync, because there is nothing to sync — one device holds the state, and both apps read it.

That also means using both is normal, and the intended way to use BudsDesk: the phone for firmware, the Mac for everything you touch during a working day.

Why this is not a wrapper

BudsDesk does not contain the phone app, does not call it, and does not read its data. There is no decompiled code in it and no extracted asset. It was built by recording what the earbuds exchanged with the phone app and then writing an independent client for that conversation — which is why it can state which parts are measured and which are not, and why it can tell you when a setting was declined instead of showing you a button that lies.

Questions

Is there a Mac version of HeyMelody?
There is no desktop build. It is a phone app published for iPhone and Android. Some storefronts offer it for Apple silicon Macs as an iPhone app, which Apple makes possible for apps that have not been withdrawn from Mac availability; whether it can reach the earbuds' control channel when run that way is not something this project has tested, and this page does not claim either way.
Does BudsDesk reuse anything from it?
No. BudsDesk shares no code, no assets and no extracted data with it. It was written by recording the traffic between the phone app and real earbuds, then writing an independent client for what the wire carries. No vendor code is decompiled into the app, and no vendor asset is redistributed.
Does BudsDesk do firmware updates?
No, and it never will. Firmware updates travel over a separate service that BudsDesk never opens. If updating firmware matters to you, the phone app is the only tool here that does it, and that is a real advantage it has.
Can I use both?
Yes. The settings live on the earbuds, so a change made in one shows up in the other. Use the phone app for firmware and for models BudsDesk has not catalogued, and BudsDesk when the earbuds are at the computer.
